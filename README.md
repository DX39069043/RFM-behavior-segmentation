# 电商用户行为分层与差异化运营分析

> 一个面向数据分析岗位的电商用户分层项目。
> 基于用户行为日志，从“**用户为什么没有购买 / 已购买用户处于什么状态**”出发，构建可解释的用户分层体系，并通过时间外验证检验分层对未来购买行为的识别能力，最终形成面向不同用户类型的运营策略建议。

------

## 1. 项目背景

在电商场景中，不同用户的行为状态差异很大：

- 有些用户浏览和互动非常活跃，但始终没有完成购买；
- 有些用户已经购买，并且具有较高的消费价值；
- 有些高价值用户近期却逐渐失去活跃；
- 如果对所有用户采用相同的营销方式，容易造成触达资源浪费。

因此，本项目希望解决两个核心问题：

1. **如何根据用户行为识别不同的用户状态？**
2. **这些分层是否真的能够识别未来更可能发生购买或流失风险的用户？**

项目最终形成：

```text
用户行为数据
      ↓
用户级特征工程
      ↓
按购买状态分流
      ↓
可解释用户分层
      ↓
时间外验证
      ↓
运营策略建议
      ↓
目标人群优先级排序
```

> **项目定位：** 本项目重点解决“用户识别与运营决策支持”问题。运营策略目前为分析后的建议，尚未直接执行营销实验，因此验证结果属于观察性时间外验证，不能直接解释为营销动作的因果效果。

------

## 2. 数据与分析框架

### 2.1 数据概况

项目使用电商用户行为日志构建月度用户面板。

核心事件包括：

- `view`：浏览
- `cart`：加购
- `purchase`：购买

数据覆盖 **2019-10 至 2020-04**，以月为单位构建用户行为特征。

项目首先将事件级数据聚合为用户级数据，使每个用户在每个月都有一组行为特征，为后续分层和时间外验证提供统一的数据基础。

### 2.2 核心特征

围绕用户的浏览、互动和购买行为，构建以下用户级特征：

| 特征                 | 含义                   |
| -------------------- | ---------------------- |
| `Total_Spending`     | 用户消费金额           |
| `Purchase_Frequency` | 用户购买次数           |
| `Recency_Days`       | 距离最近一次购买的天数 |
| `PageViews`          | 浏览页面数             |
| `Effective_Duration` | 有效停留时长           |
| `Sessions`           | 会话数                 |
| `Cart_Items`         | 加购商品数             |

其中，浏览、停留和会话行为进一步用于构造用户的**探索度（Exploration）**；加购但未购买的商品数用于衡量用户的**决策摩擦（Friction）**。

------

## 3. 用户分层

### 3.1 传统 RFM 的问题

项目最初考虑使用 RFM 对全部用户进行聚类。

但实际数据中存在大量**从未购买的用户**：

```text
Frequency = 0
Monetary = 0
```

如果直接对所有用户进行 RFM 聚类，模型很容易首先把用户区分成：

> “买过” vs “没买过”

这虽然具有统计意义，但对运营来说区分度有限。

因此，本项目没有直接对所有用户进行统一聚类，而是采用：

```text
                    用户
                     │
             是否发生过购买？
              /             \
            否               是
            │                │
       购买潜力分析        用户价值分析
            │                │
      高潜力首购          已购用户分层
```

这种设计的核心思想是：

> **先解决用户当前最重要的业务状态，再在状态内部进一步区分用户。**

------

### 3.2 未购用户：识别高潜力首购人群

对于观察期内没有购买的用户，传统 RFM 无法很好区分其购买潜力，因此重点观察两个维度：

#### Exploration：探索度

用于衡量用户对商品的主动探索程度，由以下行为综合构成：

- 浏览页面数
- 有效停留时长
- 会话数

经过 `log1p` 变换和标准化后进行组合。

#### Friction：决策摩擦

用于衡量：

> **用户已经表现出购买意图，但为什么没有完成购买？**

核心指标为：

```text
加购但最终没有购买的去重商品数
```

在数据中，大量未购用户没有加购行为，因此对 Friction 采用零膨胀场景下的 GMM 阈值识别，并设置兜底逻辑。

最终将：

```text
未购买
+
高 Exploration
+
高 Friction
```

定义为：

> **高潜力首购用户**

这里的“高潜力”表示其行为特征与后续购买具有较强关联，并不意味着已经证明营销干预能够造成增量购买。

------

### 3.3 已购用户：从 RFM 转向连续价值指数

对于已经购买的用户，购买金额、购买频次和最近购买时间都具有明确业务意义。

因此构造：

Value Index=log⁡1p(消费金额)+log⁡1p(购买频次)−log⁡1p(最近购买天数)Value\ Index = \log1p(消费金额) + \log1p(购买频次) - \log1p(最近购买天数)

在已购用户内部，以价值指数的上四分位数识别高价值用户。

随后结合用户的探索行为进一步区分：

```text
高价值用户
├── 高价值直购
└── 高价值深度互动

普通已购用户
└── 常规已购
```

此外，对于跨月完全没有行为的高价值用户，单独识别为：

> **高价值高摩擦用户**

用于支持后续召回和流失风险运营。

------

## 4. 分层结果与时间外验证

### 4.1 为什么采用时间外验证？

如果使用同一时间窗口完成：

```text
分层 → 评价
```

很容易出现信息泄漏或过拟合问题。

因此项目采用：

> **过去行为用于建模，未来行为用于验证**

例如：

```text
2019-10
建模 / 分层
    ↓
2019-11
观察实际购买
```

在正式的滚动验证中，每一轮都使用**当轮基期月份独立拟合阈值**，再使用下一月份进行验证。

因此不会使用未来月份的购买结果参与当前分层。

------

### 4.2 高潜力首购用户验证

以 2019-10 → 2019-11 为例：

| 人群         | 人数    | 次月购买率  |
| ------------ | ------- | ----------- |
| 高潜力首购   | 5,408   | **13.30%**  |
| 普通未购用户 | 128,519 | **5.41%**   |
| 差异         | —       | **+7.88pp** |

卡方检验：

```text
p ≈ 2.2 × 10⁻¹³¹
```

说明高潜力首购人群在下一月表现出了明显更高的购买率。

进一步进行滚动验证后，该分层在连续窗口中均表现出稳定的方向性差异。

这说明：

> **Exploration + Friction 的组合能够作为识别潜在首购用户的有效行为信号。**

------

### 4.3 高价值沉默用户验证

对于已经识别出的高价值用户，进一步观察：

> 用户在下一月是否完全没有任何行为？

将跨月完全沉默的高价值用户与仍然保持活跃的高价值用户进行比较。

在多个连续验证窗口中：

```text
5 / 5 个验证窗口
购买率差均显著为负
```

购买率差约为：

```text
-19.9pp ～ -31.8pp
```

说明：

> **高价值用户的跨月完全沉默，是一个具有较强稳定性的风险信号。**

因此可以将这部分用户作为高价值用户召回的重点候选人群。

------

### 4.4 分层并不是一次性标签

用户状态会随着行为变化而发生迁移。

因此项目进一步进行了固定基期的队列迁移分析：

```text
2019-10
固定分层标准
      ↓
观察后续月份
      ↓
用户是否发生状态迁移？
```

这里与滚动验证不同：

> **队列迁移分析固定使用 2019-10 拟合得到的阈值和标准化参数。**

这样可以观察同一批用户在后续月份中的状态变化，而不是每个月重新定义用户类型。

------

## 5. 从用户分层到运营

用户分层的最终目的不是得到几个标签，而是支持运营资源分配。

因此项目将：

```text
用户类型
   ↓
行为特征
   ↓
用户状态
   ↓
运营策略建议
```

进行对应。

### 5.1 高潜力首购

**行为特征：**

- 尚未购买
- 浏览和互动较活跃
- 存在加购但未购买行为

**运营建议：**

- 优先触达
- 针对加购商品进行提醒
- 提供优惠券、限时优惠等转化激励
- 降低购买决策成本

------

### 5.2 高价值深度互动

**行为特征：**

- 已有较高历史价值
- 浏览和互动程度较高

**运营建议：**

- 个性化商品推荐
- 会员权益
- 关联商品推荐
- 提高复购频率和客单价值

------

### 5.3 高价值直购

**行为特征：**

- 历史价值较高
- 购买行为较明确
- 探索行为相对较低

**运营建议：**

- 复购提醒
- 高频购买商品推荐
- 会员 / 老客权益
- 降低再次购买路径

------

### 5.4 高价值高摩擦

**行为特征：**

- 历史价值较高
- 后续月份出现完全沉默

**运营建议：**

- 老客召回
- 个性化优惠
- 历史偏好商品推荐
- 检查价格、库存、商品体验等潜在流失原因

------

### 5.5 优先级排序

用户分层解决的是：

> **“应该关注谁？”**

进一步的优先级排序解决的是：

> **“资源有限时，应该先触达谁？”**

项目保留了 Logistic Regression 作为名单内排序工具：

```text
规则分层
    ↓
圈定目标人群
    ↓
Logistic Regression
    ↓
预测未来购买概率
    ↓
目标名单内部排序
```

这里 LR **不负责重新定义用户类型**，而是对已经通过规则分层筛选出的目标人群进行优先级排序。

这种设计能够兼顾：

- **规则分层的可解释性**
- **模型排序的精细化**

------

## 6. 项目总结

### 6.1 核心分析结论

本项目最终形成了一个从行为数据到运营决策的用户分析框架：

```text
行为日志
   ↓
用户级特征
   ↓
购买状态分流
   ↓
可解释用户分层
   ↓
时间外验证
   ↓
目标人群识别
   ↓
优先级排序
   ↓
运营策略建议
```

核心发现包括：

- 未购用户中，**探索度 + 加购未购买行为**能够识别出具有更高后续购买概率的高潜力首购人群；
- 已购用户中，消费、频次和最近购买时间能够构建连续的用户价值指标；
- **高价值用户的跨月完全沉默**能够作为稳定的风险识别信号；
- 用户标签会随行为变化，因此需要结合时间窗口持续更新，而不是依赖一次性静态分群。

### 6.2 项目方法特点

与直接使用 K-Means 对全部用户进行聚类相比，本项目更强调：

**业务状态驱动 + 可解释特征 + 时间外验证**

而不是单纯追求聚类算法本身。

最终实现的是：

> **先利用业务逻辑解决“用户处于什么状态”，再利用统计模型解决“用户应该如何排序”。**

### 6.3 局限与下一步

目前项目中的时间外验证属于**观察性验证**，能够证明用户分层与未来购买行为之间存在稳定关联，但不能证明运营策略本身能够带来增量效果。

如果进入真实业务环境，下一步可以设计：

```text
目标人群筛选
    ↓
随机实验分组
    ↓
营销干预
    ↓
A/B Test
    ↓
比较增量转化率
    ↓
评估 ROI
```

进一步验证不同运营策略是否真正产生因果增量。

### 核心文件

| -------------------------------- | ------------------------------------------ |
| `analysis.py`                    | 核心特征工程、用户分层、验证及 LR 排序函数 |

| `rolling_validation_results.csv` | 滚动验证结果                               |
| `rolling_baseline_results.csv`   | 基准及排序相关结果                         |
